# Source material: Kevin Powell on CSS

From "Dealing with the 'webiness' of CSS" (kevinpowell.co) and the Scrimba Podcast episode "How not to struggle with CSS, with Kevin Powell" (podcast.scrimba.com/62/transcript). Quotes are verbatim.

## CSS deals in unknowns, so control is shared with the user

The output isn't yours to fix precisely; the medium is variable by design.

> CSS is hard because we don't have total control over the output.

> With all that at play, we can't have total control over the output, the user does!

> CSS is a language that deals with unknowns, right? You don't know the size of the person's screen.

## Embrace how it works instead of fighting it

The developer struggling with CSS is usually fighting the parts that exist to protect the reader.

> Embrace how it's meant to work instead of fighting against it, you'll start having a much better time with it.

> CSS is trying not to have information disappear... the user can still access that content.

> Once you sort of get your mind into that frame of mind, it's actually a lot of fun.

## CSS forgives, it doesn't fail

An unrecognized declaration is skipped, not fatal, which is why progressive enhancement is safe.

> CSS doesn't 'fail'. If the browser doesn't understand a line of code, it just skips it and keeps on going.

> If you try putting width purple, it doesn't break your site, it just doesn't apply the width purple.
